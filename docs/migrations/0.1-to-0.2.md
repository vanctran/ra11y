# Migrating from ra11y 0.1 to 0.2

v0.2.0 extends the MCP tool surface significantly — new tools, prompt templates, structured errors, and the bidirectional sampling rail — and cleans up several response shapes that were inconsistent across tools. Most changes are additive. The four breaking changes below affect agents that read specific fields from `suggest_fix`, `checklist`, or `coverage`, and any caller that iterates the `activeNativeWrappers` list.

Skip to the section that matches what your agent does:

## suggest_fix response shape

**Breaking.** `suggest_fix` no longer returns a top-level `suggestion` string. It returns a structured `fixPaths` object, a typed `kind` discriminant, and an `explanation` field. The canonical input parameter is now `file`; `filePath` is accepted as a deprecated alias and emits a `deprecated_param_filePath` code in `warnings`.

**Before (0.1.0):**

```json
{
  "suggestion": "Add aria-label describing the button action.",
  "confidence": "high"
}
```

**After (0.2.0):**

Mechanical fix (rule emits a searchable edit):

```json
{
  "kind": "edit",
  "explanation": "aria-hidden on a focusable element — change to inert.",
  "fixPaths": {
    "primary": {
      "label": "change aria-hidden to inert",
      "edit": { "oldText": "aria-hidden=\"true\"", "newText": "inert" }
    },
    "alternatives": [
      {
        "label": "remove from tab order before hiding",
        "description": "Add tabIndex={-1} before setting aria-hidden."
      }
    ]
  },
  "confidence": "high",
  "verifyCommand": "mcp: scan_file({ file: \"src/Modal.tsx\" }) and confirm aria/hidden-focus no longer fires",
  "verifyCommandStructured": { "tool": "scan_file", "args": { "file": "src/Modal.tsx", "ruleId": "aria/hidden-focus" } }
}
```

Guidance-only fix (no mechanical edit available):

```json
{
  "kind": "guidance",
  "explanation": "Add descriptive alt text.",
  "fixPaths": {
    "primary": {
      "label": "add descriptive alt",
      "description": "Describe what the image communicates, not its appearance."
    },
    "alternatives": []
  },
  "confidence": "high",
  "verifyCommand": "...",
  "verifyCommandStructured": { "tool": "scan_file", "args": { "file": "src/Hero.tsx", "ruleId": "media/alt-text-missing" } }
```

No violation at that location:

```json
{
  "kind": "none",
  "explanation": "No violation for media/alt-text-missing at line 12.",
  "confidence": "low",
  "verifyCommand": "...",
  "verifyCommandStructured": { "tool": "scan_file", "args": { "file": "src/Hero.tsx" } }
}
```

**Migration path:**

1. Replace reads of `response.suggestion` with `response.explanation` for the prose description.
2. To apply a mechanical fix, check `response.kind === "edit"` and use `response.fixPaths.primary.edit` — the `oldText`/`newText` pair is widened to a unique anchor window so a literal find-and-replace matches exactly once.
3. When the fix is guidance-only, `kind === "guidance"` and `fixPaths.primary.description` carries the prose instruction.
4. The `apply_fix` tool in v0.2.0 accepts the `fixPaths.primary.edit` object directly (when `allowWrite: true` is set in session config).

## checklist response shape

Two breaking changes in `checklist`:

### automatedCoverage trimmed to a gloss

**Breaking.** `checklist.summary.automatedCoverage` in 0.1.0 contained the full per-standard block with `criteriaTotal`, `criteriaAutomatable`, `criteriaAutomatablePassing`, and `failingAutomatedCriteria`. In 0.2.0 it is trimmed to a one-field gloss: `{ standardId, automatedCriteriaPassRate }` (or an array of these when multiple standards are active). The full block is canonical in `coverage` only.

**Before (0.1.0):**

```json
{
  "summary": {
    "automatedCoverage": {
      "standardId": "wcag22",
      "criteriaTotal": 87,
      "criteriaAutomatable": 34,
      "criteriaAutomatablePassing": 28,
      "failingAutomatedCriteria": ["wcag22:1.4.3", "wcag22:2.1.1"]
    }
  }
}
```

**After (0.2.0):**

```json
{
  "summary": {
    "automatedCoverage": {
      "standardId": "wcag22",
      "automatedCriteriaPassRate": 0.82
    }
  }
}
```

**Migration path:** Call `coverage` when you need the full per-standard breakdown. Both tools link to each other via `nextStep` / `nextStepStructured`.

### untargeted count renamed

**Breaking.** The `untargeted` count field on `checklist.summary` (and `manualUntargetedCount` on `coverage`) is renamed to `untargetedCriteria` across all tools. Agents reading the old names get `undefined`.

**Before (0.1.0):**

```json
{ "summary": { "untargeted": 18 } }
```

```json
{ "manualUntargetedCount": 18 }
```

**After (0.2.0):**

```json
{ "summary": { "untargetedCriteria": 18 } }
```

```json
{ "untargetedCriteria": 18 }
```

The gated list field is also renamed: `manualUntargeted` → `untargetedCriteriaList` (emitted only when `showUntargeted: true`).

## coverage response shape

The `manualUntargetedCount` rename is covered above. One additional change: `manualUntargeted` (the full list) is no longer returned by default. Pass `showUntargeted: true` to restore the list as `untargetedCriteriaList`. The count `untargetedCriteria` is always present.

## activeNativeWrappers shape

**Breaking.** The `activeNativeWrappers` field changed from a flat `string[]` to a tagged object list. The two companion fields — `activeNativeWrappersBySource` and `sessionNativeWrappers` — are removed. `sessionOverridesNote` prose continues to appear when session-added wrappers exist.

**Before (0.1.0):**

```json
{
  "activeNativeWrappers": ["Button", "IconButton"],
  "activeNativeWrappersBySource": {
    "fromConfig": ["Button"],
    "fromSession": ["IconButton"],
    "fromAutoDetect": []
  },
  "sessionNativeWrappers": ["IconButton"]
}
```

**After (0.2.0):**

```json
{
  "activeNativeWrappers": [
    { "name": "Button", "source": "config" },
    { "name": "IconButton", "source": "session" },
    { "name": "Link", "source": "autoDetect", "confirmed": true },
    { "name": "Card", "source": "autoDetect", "confirmed": false }
  ],
  "sessionOverridesNote": "1 wrapper added by this session's configure() call, not in ra11y.config.ts. ..."
}
```

`source` is one of `"config" | "session" | "autoDetect"`. `confirmed` appears only on `autoDetect` entries: `true` when the one-hop AST probe found a native interactive root in the defining file; `false` when the scanner considered the name but could not confirm it.

**Migration path:**

- To get all active wrapper names: `wrappers.map(w => w.name)`.
- To get config-file wrappers: `wrappers.filter(w => w.source === "config").map(w => w.name)`.
- To get session-added wrappers (replaces `sessionNativeWrappers`): `wrappers.filter(w => w.source === "session").map(w => w.name)`.
- To get auto-detected confirmed wrappers: `wrappers.filter(w => w.source === "autoDetect" && w.confirmed).map(w => w.name)`.

This shape is emitted by `scan`, `scan_project`, `scan_file`, `scan_diff`, `list_suppressions`, and any other tool that emits wrapper meta.

## Input compatibility

These v0.2.0 changes are NOT breaking — they are backward-compatible additions or soft deprecations:

- `suggest_fix`: `filePath` parameter is accepted alongside the canonical `file` parameter. When `filePath` is used, the response carries `warnings: ["deprecated_param_filePath: use 'file' instead"]`. Migrate when convenient.
- `configure` tool: the `configure` MCP tool dispatches on the same parameters as the CLI `--configure` flag. Agents calling `configure` with 0.1.0 parameters continue to work.
- `checklist`: `reviewNeeded` is not present in the 0.1.0 response shape — checklist items gained structured `priority` and `wcagPrinciple` fields in v0.2.0 as additive properties, not renames of `reviewNeeded`.
