# `aria/valid-attr`
- **Severity:** error
- **Scope:** node
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
aria-* attributes must be defined by WAI-ARIA 1.2. Misspelled or invented aria attributes are silently ignored by assistive technology.
## Why it matters
Screen readers and other assistive tech only honor the aria-* states and properties defined by the WAI-ARIA spec. An attribute like aria-lable or aria-foo is not announced, not propagated to the accessibility tree, and produces no behavior whatsoever — the author's intent is lost with no runtime warning.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined; states, properties, and values that can be set by the user can be programmatically set; and notification of changes to these items is available to user agents, including assistive technologies.
## Good example
```tsx
<div role="button" aria-pressed="false">Toggle</div>
```
## Bad example
```tsx
<div role="button" aria-preessed="false">Toggle</div>
```
