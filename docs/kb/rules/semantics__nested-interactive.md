# `semantics/nested-interactive`
- **Severity:** error
- **Scope:** document
- **Satisfies:** `wcag22:4.1.2`, `wcag21:4.1.2`
- **Applies to:** .html, .htm, .tsx, .jsx
## What it checks
Interactive elements (links, buttons, form controls, elements with interactive ARIA roles) must not be nested inside other interactive elements.
## Why it matters
Nesting one interactive control inside another is invalid per the HTML content model for <a> and <button>, and the resulting DOM has no well-defined accessibility semantics. Click events bubble to the outer control, focus order is ambiguous, and screen readers typically announce the outer element's role while the user is operating the inner one — so the inner element's name and role can no longer be programmatically determined.
## Normative quote
> For all user interface components (including but not limited to: form elements, links and components generated by scripts), the name and role can be programmatically determined.
## Good example
```tsx
<a href="/settings">
  Settings
  <svg aria-hidden="true">...</svg>
</a>
```
## Bad example
```tsx
<a href="/card">
  <button type="button">Action</button>
</a>
```
