# 2.3.2 Three Flashes

**Level:** AAA | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#three-flashes>

## Why manual

This criterion requires runtime measurement of actual flash frequency across rendered frames. Static analysis can flag elements with animation properties (CSS `animation`, `transition`, or `<video>`), but it cannot measure the rendered flash rate in Hz or determine whether content exceeds three flashes per second.

The related finder (`flashing-content`) surfaces candidate elements; the attestation step confirms flash rate through runtime testing.

## What to verify

> "Web pages do not contain anything that flashes more than three times in any one second period."

No threshold exceptions apply — unlike 2.3.1, this criterion permits no flashing above 3 Hz regardless of luminance or area. Applies to all content: video, GIF, Canvas, CSS animation, SVG animation, JavaScript-driven DOM changes.

## Common failure modes

- CSS `animation` or `transition` that cycles through high-contrast colors faster than 3× per second.
- Animated GIF or WebP with a frame rate exceeding 3 fps for high-contrast frames.
- JavaScript polling that toggles element visibility or class at intervals shorter than 333 ms.
- Video content with strobe lighting at more than 3 flashes per second.
- Canvas animation rendering high-contrast alternating frames above 3 Hz.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/2.3.2`):

- Use the Photosensitive Epilepsy Analysis Tool (PEAT) or equivalent to measure flash rate on any animated content.
- Confirm no content flashes more than 3 times in any 1-second window.
- For CSS animations: calculate effective flash rate from `animation-duration` and color-alternation steps.
- For video: review frame-by-frame at 30 fps or higher to detect strobe effects.

Evidence: PEAT report or equivalent tool output showing no violations, plus list of animated elements reviewed.
