# 2.4.8 Location

**Level:** AAA | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#location>

## Why manual

"Location information is available" depends on what pages exist in the site and whether a wayfinding mechanism (breadcrumb, site map, progress indicator) is present and semantically meaningful. Static analysis cannot know whether a given page is part of a multi-page set or whether a visual breadcrumb is accessible and accurate.

## What to verify

> "Information about the user's location within a set of web pages is available."

Applies when a page belongs to a set (e.g., multi-step wizard, site with section hierarchy). Acceptable mechanisms include: breadcrumb navigation, site map, progress indicator (step X of N), or highlighted navigation item showing current location. The mechanism must be available to all users including those using assistive technology.

## Common failure modes

- Multi-page checkout or wizard with no step indicator (no "Step 2 of 4" or equivalent).
- Breadcrumb present visually but implemented with `<div>` and no `aria-label="breadcrumb"` or `aria-current="page"`.
- Site navigation with no highlight or indication of current section.
- Site map exists but is not linked from any page.
- Progress indicator uses color alone to indicate current step (also a 1.4.1 failure).

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/2.4.8`):

- Identify all multi-page sequences and site sections in the application.
- For each, confirm a location mechanism is present (breadcrumb, progress indicator, highlighted nav).
- Verify the mechanism is keyboard-accessible and announces current location to screen readers (e.g., `aria-current="page"` on the active breadcrumb item).
- For wizards: confirm the current step is announced on page load.

Evidence: annotated screenshots of each location mechanism, plus screen reader output confirming current-location announcement.
