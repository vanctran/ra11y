# 2.4.12 Focus Not Obscured (Enhanced)

**Level:** AAA | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#focus-not-obscured-enhanced>

## Why manual

The rule `focus/not-obscured` covers the minimum version (2.4.11: no element is fully hidden). This enhanced criterion requires that **no part** of the focused component is hidden. Verifying partial obscurance requires rendering context — the exact pixel positions of sticky headers, fixed footers, and focused elements must be known at runtime.

## What to verify

> "When a user interface component receives keyboard focus, no part of the component is hidden by author-created content."

Stricter than 2.4.11 (which allows partial hiding as long as the component is not fully hidden). Here, the entire focused component must be fully visible — no pixel of it may be covered by author-created overlays, sticky headers, drawers, or banners.

## Common failure modes

- Sticky header covers the top portion of the first focusable element in a scrolled-down section.
- Fixed cookie consent banner at the bottom covers focused buttons near the page footer.
- A floating action button overlaps a focused input field in the same area.
- Off-canvas menu partially slides over content and covers a focused element at the edge.
- Tooltip triggered by focus obscures part of the element that triggered it.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/2.4.12`):

- Tab through every interactive element while any sticky/fixed content is present.
- Confirm the entire focused component is visible — no part hidden by sticky headers, footers, banners, or overlays.
- Pay special attention to: sticky nav bars, cookie/consent banners, floating action buttons, chat widgets, off-canvas drawers.
- Test at multiple viewport sizes where sticky content heights differ.

Evidence: screen recording of full keyboard traversal with sticky elements present, annotated to show no partial obscurance.
