# 3.3.6 Error Prevention (All)

**Level:** AAA | **Standard:** WCAG 2.2
**Spec:** <https://www.w3.org/TR/WCAG22/#error-prevention-all>

## Why manual

Whether a submission is reversible, checkable, or confirmable is a runtime behavior. Static analysis can detect `<form>` elements but cannot determine whether a backend supports undo, whether validation feedback is presented to the user before final submission, or whether a review-and-confirm step exists. The related finder (`error-prevention`) surfaces form candidates; this criterion extends the requirement to all submissions, not just legal/financial/data ones.

## What to verify

> "For Web pages that require the user to submit information, at least one of the following is true:
> Submissions are reversible.
> Data entered by the user is checked for input errors and the user is provided an opportunity to correct them.
> A mechanism is available for reviewing, confirming, and correcting information before final submission."

Extends 3.3.4 (Error Prevention — Legal, Financial, Data) to ALL form submissions. Every form, not just high-stakes ones, must provide at least one of: reversibility, error checking + correction opportunity, or review step.

## Common failure modes

- Search form that immediately submits with no chance to correct a typo.
- Contact or feedback form with no validation before send and no confirmation step.
- Settings form that applies changes immediately on field change with no Save button.
- Profile update form that does not confirm success or allow undo after submission.
- Comment form that posts immediately without review or edit capability.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/wcag22/3.3.6`):

- Identify every form submission in the application.
- For each, confirm at least one mechanism: (a) undo/delete after submission, (b) inline validation before submit, or (c) review/confirm step.
- Verify inline validation is accessible: errors announced via `aria-live` or linked to fields via `aria-describedby`.
- Note forms where no mechanism is present — these are failures.

Evidence: form inventory with mechanism noted for each; screen recording of validation feedback and any review/undo flows.
