# 9.4.1.1 Parsing (EN 301 549)

**Level:** base | **Standard:** EN 301 549 v3.2.1
**Spec:** <https://www.etsi.org/deliver/etsi_en/301500_302000/301549/03.02.01_60/en_301549v030201p.pdf> (clause 9.4.1.1)

## Why manual

This criterion incorporates WCAG 2.1 4.1.1 by reference, which is **obsolete in WCAG 2.2**. EN 301 549 v3.2.1 references WCAG 2.1; organizations targeting EN 301 549 conformance must still address this criterion. Static rule `parsing/duplicate-id` covers the duplicate ID aspect. HTML validation is required for full compliance.

## What to verify

EN 301 549 9.4.1.1 incorporates WCAG 2.1 4.1.1:
> "In content implemented using markup languages, elements have complete start and end tags, elements are nested according to their specifications, elements do not contain duplicate attributes, and any IDs are unique, except where the specifications allow these features."

Note: EN 301 549 v3.2.1 references WCAG 2.1, not WCAG 2.2. Organizations targeting only WCAG 2.2 may note that WCAG 2.2 removed this criterion; for EN 301 549 compliance it remains applicable.

## Common failure modes

- Duplicate `id` attribute values (partially caught by `parsing/duplicate-id` rule).
- Elements with missing end tags in hand-authored HTML.
- Incorrectly nested elements contrary to the HTML specification.
- Duplicate attributes on a single element.

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/en301549/9.4.1.1`):

- Run the `parsing/duplicate-id` rule via `ra11y scan` to check for duplicate IDs.
- Run HTML validation via the W3C Nu Html Checker (<https://validator.w3.org/nu/>) against rendered output.
- Review validator output for nesting errors, missing end tags, and duplicate attributes.

Evidence: W3C validator report showing zero parsing errors, plus `ra11y scan` output showing no `parsing/duplicate-id` violations.
