# 4.1.1 Parsing (Section 508)

**Level:** base | **Standard:** Section 508 (2017 refresh)
**Spec:** <https://www.access-board.gov/ict/#chapter5-software> (incorporates WCAG 2.0 4.1.1 by reference)

## Why manual

This criterion is **obsolete in WCAG 2.2** and was removed from that standard. Section 508 (2017 refresh) incorporates WCAG 2.0 success criteria by reference. Organizations subject to Section 508 that are also tracking WCAG 2.2 conformance should note that WCAG 2.2 no longer includes 4.1.1 as a testable criterion.

For Section 508 conformance specifically, 4.1.1 parsing requirements from WCAG 2.0 still apply. Static rule `parsing/duplicate-id` covers the duplicate ID aspect. No finder is currently assigned.

## What to verify

WCAG 2.0 4.1.1 (incorporated by Section 508):
> "In content implemented using markup languages, elements have complete start and end tags, elements are nested according to their specifications, elements do not contain duplicate attributes, and any IDs are unique, except where the specifications allow these features."

WCAG 2.2 note on removal: "WCAG 2.2 has removed one success criterion, 4.1.1 Parsing. Authors required by policy to conform with WCAG 2.0 or 2.1 may need to continue to test and report 4.1.1."

## Common failure modes

- Duplicate `id` attribute values in a page (partially caught by `parsing/duplicate-id` rule).
- Elements with missing end tags in hand-authored HTML.
- Incorrectly nested elements (e.g., block elements inside inline elements contrary to HTML spec).
- Duplicate attributes on a single element (rare in generated markup, possible in templates).

## Attestation guidance

To attach evidence to an `attest` call (`ra11y-kb://criteria/section508/4.1.1`):

- Run the `parsing/duplicate-id` rule via `ra11y scan` to check for duplicate IDs.
- Run HTML validation via the W3C Nu Html Checker (<https://validator.w3.org/nu/>) against rendered output.
- Review validator output for nesting errors, missing end tags, and duplicate attributes.
- Note: if your conformance target is WCAG 2.2, this criterion does not apply; record "not applicable — WCAG 2.2 target" as attestation.

Evidence: W3C validator report showing zero parsing errors, or explicit record that WCAG 2.2 target makes this criterion inapplicable.
